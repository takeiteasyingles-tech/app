# 07 · v1 features

Status: foundation landed (schema, contracts, permissions, constants, stubs). Five features are built on top of it in parallel (A–E below). This spec is authoritative for v1; 04-architecture still governs everything it does not mention.

The foundation is **frozen**: feature agents add to it only additively (a new optional field, a new endpoint, a new constant) and record the change here. Never rename or reshape what is listed below, never edit migration 0007 once it is applied anywhere, and put any further schema change in a new numbered migration (0008, …).

## 1. Scope and decisions (with the client)

| # | Feature | Decision |
|---|---|---|
| A | Password recovery by e-mail; profile name editing | Self-service "Esqueci a senha" sends a one-time link by e-mail through **Resend** (HTTP API, no SDK needed). The link is the existing `#/entrar?reset=<token>`, consumed by the existing `ResetForm` and `POST /api/auth/reset/consume`. It is valid 1 hour (the admin-issued link stays 24 h). The request always answers 204, so it never reveals whether an e-mail has an account. Perfil gets "Trocar senha" (existing `POST /api/auth/password`) and editing of nome completo / nome de exibição (existing `PUT /api/me/profile`, which already validates `fullName`/`name` like signup). |
| B | Season test + automatic PDF certificate | One test per **season** (20 episodes). Questions are **drafted by AI** (Workers AI, or an agent over MCP) and **approved by staff**; only approved questions reach learners. Pass mark: a percentage per season (default 70 %). The test opens when **every published episode of the season is done**. Passing awards `season_pass:{n}` (100 pontos) once and issues a **certificate** once, with a short public code; anyone can verify it on a public page. The PDF is rendered on first download and cached in R2. |
| C | NPS per episode; learning statistics | On Concluído the learner rates the episode 1–5 stars, with an optional comment (≤ 1000 chars). One rating per learner and episode, editable (upsert). Staff see the list, a per-episode summary with an NPS-style score, per-learner statistics and a course funnel. |
| D | MCP server in tie-admin; season editor | An AI agent (Claude) edits content through an **MCP** endpoint in tie-admin, authenticated by **API tokens** that admins create. Agents can read, edit and draft, never publish: humans publish in the admin. The admin gains a CRUD for seasons (title, synopsis, test settings). |
| E | Mic page redesign | Student-app UI only (`screens/maggie`). No foundation changes; any contract addition follows the additive rule. |

All five are PROD additions (01-features has no prototype counterpart for them). Screen-level departures from the prototype go to 05-foundation-notes § "Accepted production deviations" → "v1 features".

## 2. Data model (migration `packages/db/migrations/0007_v1.sql`)

Additive only. All new tables are STRICT, timestamps unix ms, ids text (`newId()` ULIDs unless noted).

| Object | Columns / meaning |
|---|---|
| index `ix_ott_user` | `one_time_tokens(user_id, kind, expires_at)`: per-user throttle of reset e-mails. |
| `seasons` + columns | `test_pass_pct` INT 0..100 default 70 · `test_question_count` INT 1..100 default 20 (target size: the AI draft defaults to it, publishing needs at least this many approved questions; learners answer **every** approved question) · `test_published` 0/1 default 0 · `test_published_at`, `test_published_by` · `updated_at` default 0, `updated_by` (season editor stamps). |
| `season_test_questions` | `id` PK · `season_n` → seasons ON DELETE CASCADE · `sort` · `part_title` default '' · `q` · `opts` JSON / `answer_idx` (choice) and/or `accept` JSON (typed, stored normalized with `norm()`) · `show` (right answer as shown) · `audio` (TTS text) · `rev` (where to review) · `ep_num` (no FK, like `ebook_test_questions`) · `status` draft/approved/rejected · `source` ai/agent/staff · `created_at`, `updated_at`, `updated_by`. CHECK: choice pair or accept. Index `(season_n, status, sort)`. |
| `season_test_answers` | PK `(user_id, question_id)` · `choice_idx` / `text_value` · `correct` · `updated_at`. Cascades from users and questions. |
| `season_test_results` | PK `(user_id, season_n)` · `score`, `total`, `score_pct` (0..100) · `passed` · `best_pct` · `attempts` · `submitted_at` (0 = redo in progress, as for e-books) · `passed_at` (first pass, never cleared by a redo). No FK to seasons. |
| `certificates` | `id` PK · `code` UNIQUE (`TIE-XXXX-XXXX`) · `user_id` → users CASCADE · `season_n` · `full_name_snapshot`, `season_title_snapshot` (frozen at issue) · `score_pct` · `issued_at` · `r2_key` (cached PDF, NULL until first render) · `revoked_at`, `revoked_by`, `revoke_reason`. UNIQUE `(user_id, season_n)`. |
| `point_rules` row | `season_pass` = 100, no daily cap, verifiable (INSERT OR IGNORE). |
| `lesson_feedback` | `id` PK · `user_id` → users CASCADE · `episode_num` → episodes (no cascade: an episode with ratings is in use) · `stars` CHECK 1..5 · `comment` NULL or ≤ 1000 chars · `created_at`, `updated_at`. UNIQUE `(user_id, episode_num)`. Indexes `(episode_num, stars)`, `(updated_at)`. |
| index `ix_progress_ep` | `episode_progress(episode_num, done_at)` for the funnel. |
| `api_tokens` | `id` PK · `name` · `token_hash` UNIQUE (sha256 hex of the plaintext) · `token_prefix` (first 12 chars, display) · `created_by` → users CASCADE · `scopes` JSON · `created_at`, `last_used_at`, `expires_at`, `revoked_at`, `revoked_by`. |

The season test is served **live from D1**, not compiled into a content release: publishing/unpublishing a test and approving questions take effect immediately. Season `title`/`synopsis` still reach learners through `catalog.json` on the next release.

### A · Auth e-mail + Perfil (owner: agent A)

- Files: `apps/app/worker/src/routes/auth.ts` (`resetRequest`), new `apps/app/worker/src/mail/` (Resend client + pt-BR template, plain text + simple HTML without remote images), `apps/app/web/src/screens/entrada/Entrar.tsx` ("Esqueci a senha" form), `screens/perfil` (trocar senha, editar nomes).
- Flow: rate limit (`RL_AUTH`, keyed by IP and by e-mail) → Turnstile → look up the user by e-mail (COLLATE NOCASE) → only for `status = 'active'` accounts with a password set (staff invites keep their own link) → if the user has fewer than `LIMITS.resetMailsPerHour` live reset tokens (`ix_ott_user`), insert `one_time_tokens(kind 'reset', expires_at = now + DURATIONS.resetEmailTokenMs)` with `sha256(randomToken())` and send `${APP_ORIGIN}/#/${RESET_LINK_ROUTE}?reset=<token>` → always 204, with the same timing whether or not anything was sent (send through `waitUntil`). Audit `auth.reset_request` with the user as actor, no e-mail in the diff.
- Resend: `POST https://api.resend.com/emails` with `Authorization: Bearer ${RESEND_API_KEY}`, body `{from: MAIL_FROM, to, subject, html, text}`. Without the key: `console.log` the link (dev and tests). A failed send is logged, never surfaced.
- The admin reset link (`POST /admin-api/users/:id/reset-link`, 24 h) and `reset/consume` stay as they are; consuming already revokes sessions.
- Perfil: name fields use `FullName` / `ShortName` rules already enforced by `PUT /api/me/profile`; password change uses `POST /api/auth/password` (other sessions revoked, this one rotated). UI copy pt-BR.

### B · Season test + certificates (owner: agent B)

- Files: `apps/app/worker/src/routes/seasons.ts` + `learning/seasonTest.ts`, `routes/certificates.ts` + a PDF module (pdf-lib or a hand-written single-page PDF; fonts self-hosted, no remote fetch), `apps/admin/worker/src/routes/seasonTest.ts` (replace the stub), admin screens (season test editor under the season, certificates list), student screens (season test, certificates in Perfil/Conquistas, public verification page `#/certificado/<code>` reachable signed out), demo drafter in `packages/shared/src/demo` (draft questions from the episodes' `visual` words and `awayExp` when AI is unavailable), prompt `season_test_draft` (seed file + `AI_PROMPT_KEYS.seasonTestDraft`, with a built-in fallback).
- Unlock: published episodes of the season (`episodes.status = 'published' AND season_n = ?`), all in `episode_progress.done_at IS NOT NULL` → `seasonTestUnlocked`.
- Grading as the e-book test (`learning/grade.ts`): choice by index, typed by `accept.includes(norm(v))`. `score_pct = scorePct()`, pass with `seasonTestPassed(pct, test_pass_pct)`. On submit, one D1 batch: answers, `season_test_results` upsert (attempts + 1, best_pct, passed_at on first pass), and on the first pass `certificates` insert (`certificateCode()`, retry on a UNIQUE clash, `full_name_snapshot` from profiles.full_name, season title) and `award('season_pass', 'season_pass:{n}')`. A later pass never reissues.
- Admin: approve/reject in bulk; staff edits keep the status, **MCP edits reset to draft**; publish refuses (409 with `publishProblems`) when approved < `test_question_count` or the season has no published episode. Unpublishing hides the test but keeps results and certificates. Every mutation audited (`season_test.question.create|update|delete|review|draft`, `season_test.publish`, `certificate.revoke|reinstate`).
- Certificate PDF: pt-BR copy ("Certificado de conclusão", name, "Temporada N · título", date, code and verification URL). Cache at `certificateR2Key(uid, id)`; serve with `Content-Type: application/pdf`, `Cache-Control: private, no-store`.
