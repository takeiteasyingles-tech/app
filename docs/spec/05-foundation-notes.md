The foundation (F0) has been built and verified. The first section lists known issues; each slice applies the ones that fall in its area. The second section lists conventions every slice follows.

## Conventions for parallel slices

- **Ownership.** Only touch your owned directories. Shared contracts live in `@tie/shared`. If a contract must change, make an additive change and report it.
- **Dependencies.** They are installed at the root. Do not run `npm install` unless you must (`-w <ws>`, and retry on a lock error).
- **Local servers.** Never run anything on the default ports when the parity harness provides slots. Use the slot ports, persist dirs and out dirs it assigns to you.
- **Typecheck and tests.** Scope them to your own workspace or files. Other slices are being edited at the same time, so errors in other slices' directories are not yours to fix.

## Accepted production deviations

Screens that knowingly depart from the prototype's markup (the golden rule's "same DOM/classes"), because the prototype had a placeholder, a layout defect or a weaker behaviour there. Every behaviour in 01-features still works. The DOM-signature diffs against `prototipo/` for these routes are expected.

### A1: Admin backend (`apps/admin/worker`)

The admin API has no prototype counterpart; these are the choices that go beyond (or tighten) spec 04 §3. Notes #1 and #3 above are implemented here. Tests: `npx vitest run --config apps/admin/worker/test/vitest.config.mjs`.

| Area | Behaviour | Why |
|---|---|---|
| Contracts (additive) | `StaffPassword` (min 10) on invite accept; `adminAccountApi.password` (`POST /admin-api/auth/password`, any staff role, kept out of `adminApi` because every endpoint there names a permission); `AssistantCreateBody` (optional `persona`, needs `ai.persona`); `AdminStats` gains `users.activeToday`, `ai.minutesThisMonth`, `ai.failureRate24h`. | Notes #1 and #3; the dashboard numbers the task asks for. |
| Login | A learner (no staff role) with the right password gets `invalid_credentials`, like a wrong password. Turnstile actions: `login` (login) and `invite` (invite accept); the admin SPA must render its widgets with those actions. | The panel stays invisible to learners; production Turnstile checks the action. |
| Invites | An invite only names a new email or an existing account that has **no password** (e.g. the bootstrapped super_admin) and that the inviter may manage (`canManage` over all its roles, so an admin never invites another admin or the super_admin). An existing account with its own password answers 409 `conflict` with `details.userId`: give the role with `PUT /users/:id/roles/:role`, and the person signs in with their own password. At accept, the creator must still be active, still grant the role and still manage every role the target holds now; the target must still have no password (a learner who registered the email after the invite was made voids it). The claim re-checks the target in SQL, in the same batch. Accepting sets the password and ends the account's other sessions. One live invite per email, one live reset link per account. | The invite URL is handed to the inviter, so accepting it must never take over an account that someone already uses. |
| Staff accounts | Suspend, delete, reset link, progress reset and role grant/revoke on a staff member need authority over every role they hold (admin over editor/moderator, super_admin over admin). Nobody acts on their own account or roles, except resetting their own learner progress. Revoking the last role ends the account's admin sessions. | Stops lateral takeovers between admins. |
| Audit | Every audit row is written in the same D1 batch as its mutation (prompt saves via `auditIf`, guarded on the version claim). A diff over 30,000 characters is reduced field by field, largest first, before worker-core's 32,000-character cap: arrays keep their changed positions (`items`), objects keep their changed keys, strings keep the first difference, and each side keeps `size` and `sha256`. A queue page that carries transcript excerpts writes `moderation.excerpts_read`. | "Every mutation audited with diff" holds for large content edits too. |
| Plans | `PUT /plans/:id` with `active:false` answers 409 `in_use` while users are assigned, the same rule as DELETE. | Assigned learners would otherwise fall back to the default quota without notice. |
| Users | Delete is a hard delete (cascade, R2 `users/{id}/` purged), as the learner's own deletion. The admin progress reset keeps flagged Mic sessions. | LGPD; flagged sessions are moderation evidence (spec 06 "Reset progress"). |
| Content | Deletes answer 409 `in_use` while learner data (scores, answers, progress, earned badges, Mic sessions) or other content points at the row.
